---
title: Nested Relation Filtering
description: Filter records based on fields of related models — traverse forward relations, reverse relations, and multi-level relation chains.
---

Cerial supports filtering records based on the fields of related models. You can traverse forward relations, reverse relations, and even multi-level relation chains to build expressive queries.

## Basic Nested Filtering

Filter on a related model's fields by nesting conditions under the relation field name:

```typescript
// Find users whose profile bio contains 'developer'
const users = await client.db.User.findMany({
  where: {
    profile: { bio: { contains: 'developer' } },
  },
});
```

A relation to a single record (`Relation`, `Relation?`) takes the related model's filter directly. A relation to many records (`Relation[]`) takes `some`, `every` or `none` around that filter, see [Reverse Relations](#reverse-relations).

## Forward Relations

Forward relations are defined with the `@field()` decorator and represent a direct reference from one model to another:

```typescript
// Schema:
// model Post {
//   authorId Record
//   author Relation @field(authorId) @model(User)
// }

// Find posts by a specific author name
const posts = await client.db.Post.findMany({
  where: {
    author: { name: 'Alice' },
  },
});
```

## Reverse Relations

Reverse relations are the inverse of forward relations. They represent the "has many" side. An array relation filter takes one of three quantifiers, each holding a filter on the related model:

| Quantifier | Matches records where |
|---|---|
| `some` | at least one related record matches |
| `every` | every related record matches, and there is at least one |
| `none` | no related record matches |

```typescript
// Schema:
// model User {
//   posts Relation[] @model(Post)
// }

// Find users who have at least one published post
const users = await client.db.User.findMany({
  where: {
    posts: { some: { status: 'published' } },
  },
});
```

Any other key directly under an array relation, such as `posts: { status: 'published' }`, is rejected with an error that says to use `some`, `every` or `none`.

## Multiple Conditions on Related Fields

You can apply multiple conditions to the related model's fields. All conditions within one relation filter are ANDed together: a single related record must match all of them:

```typescript
// Find users who have posts about TypeScript created in 2024
const users = await client.db.User.findMany({
  where: {
    posts: {
      some: {
        title: { contains: 'TypeScript' },
        createdAt: { gte: new Date('2024-01-01') },
      },
    },
  },
});
```

## Multi-Level Nesting

You can chain nested filters through multiple levels of relations:

```typescript
// Find posts where the author works at a tech company
const posts = await client.db.Post.findMany({
  where: {
    author: {
      company: {
        name: { startsWith: 'Tech' },
      },
    },
  },
});
```

```typescript
// Find categories that contain posts by active users
const categories = await client.db.Category.findMany({
  where: {
    posts: {
      some: {
        author: {
          isActive: true,
          role: { in: ['admin', 'editor'] },
        },
      },
    },
  },
});
```

## Using All Filter Operators

All standard filter operators work inside nested relation filters — [comparison](/filtering/comparison), [string](/filtering/string-operators), [array](/filtering/array-operators), [logical](/filtering/logical-operators), and [special](/filtering/special-operators) operators:

```typescript
const users = await client.db.User.findMany({
  where: {
    posts: {
      some: {
        // Comparison
        viewCount: { gte: 100 },
        // String
        title: { startsWith: 'Guide' },
        // Array
        tags: { hasAny: ['typescript', 'javascript'] },
        // Special
        deletedAt: { isNull: true },
      },
    },
  },
});
```

### Logical Operators in Nested Filters

:::caution
`AND`, `OR` and `NOT` in a relation to a single record are not yet available in the current release. They will ship in an upcoming version. Before that, such a filter was ignored and every row came back.
:::

`AND`, `OR` and `NOT` work inside a relation filter, with the same shapes as at the top level: `AND` and `OR` take an array of filters, `NOT` takes one filter. On a relation to a single record they apply to the related record:

```typescript
// Posts whose author is called Ada or Grace
const posts = await client.db.Post.findMany({
  where: {
    author: {
      OR: [{ name: 'Ada' }, { name: 'Grace' }],
    },
  },
});
```

```typescript
// Posts by an active author who is not an admin
const posts = await client.db.Post.findMany({
  where: {
    author: {
      isActive: true,
      NOT: { role: 'admin' },
    },
  },
});
```

They nest (`OR` containing `AND`), and a logical operator beside a plain field in the same relation filter is ANDed with it, as at the top level. The same filter behaves the same in `findMany`, `findOne`, `count`, `exists`, `updateMany` and `deleteMany`.

A relation filter that has keys but resolves to no condition throws instead of matching every row, so a tenant-scoped `where` can no longer silently widen.

On a relation to many records, `AND`, `OR` and `NOT` go **inside** a quantifier. Directly under the relation they are rejected with an unknown-key error, the same as any other key that is not `some`, `every` or `none`:

```typescript
// Users with at least one post that is published or featured
const users = await client.db.User.findMany({
  where: {
    posts: {
      some: {
        OR: [{ status: 'published' }, { status: 'featured' }],
      },
    },
  },
});
```

```typescript
// Wrong: rejected, wrap the filter in some, every or none
const users = await client.db.User.findMany({
  where: {
    posts: { OR: [{ status: 'published' }, { status: 'featured' }] },
  },
});
```

Inside a quantifier the operators filter the related records of that one quantifier, so `every: { OR: [...] }` means every post matches at least one branch.

## Combining Nested and Top-Level Filters

Nested relation filters can be combined with direct field filters on the parent model:

```typescript
const users = await client.db.User.findMany({
  where: {
    // Direct field filter
    isActive: true,
    age: { gte: 18 },
    // Nested relation filter
    posts: { some: { status: 'published' } },
    profile: { bio: { isNone: false } },
  },
});
```

## Works Across All Query Methods

Nested relation filters work in `where` clauses for all query methods that support filtering:

```typescript
// Count users with published posts
const count = await client.db.User.count({
  posts: { some: { status: 'published' } },
});

// Check if any user has a verified profile
const hasVerified = await client.db.User.exists({
  profile: { isVerified: true },
});

// Update users who have overdue tasks
await client.db.User.updateMany({
  where: {
    tasks: { some: { dueDate: { lt: new Date() } } },
  },
  data: { hasOverdueTasks: true },
});

// Delete posts by inactive authors
await client.db.Post.deleteMany({
  where: {
    author: { isActive: false },
  },
});
```
