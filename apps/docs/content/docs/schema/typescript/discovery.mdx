title: Finding Your Schemas
description: The three ways Cerial finds TypeScript schemas, how they combine, how to exclude a module, and why generation runs your code.
---

:::caution
This feature is not yet available in the current release. It will ship in an upcoming version.
:::

Cerial finds TypeScript schemas three ways: by the `*.schema.ts` file suffix, through an entry module that calls `defineSchema`, and through a list of files in `cerial.config.ts`. They add up. Use one, or mix them.

With no config and no entry module, the suffix alone is enough: put `*.schema.ts` files in a `schemas` or `schema` folder (or anywhere under a path you point `cerial generate` at) and run `cerial generate`.

## The three modes

| Mode | Reach for it when | You write |
|---|---|---|
| Suffix | Schemas live together in one folder | `user.schema.ts` files |
| Entry module | Schemas live beside the code that uses them | A module with `export default defineSchema({ models: [...] })` |
| Listed files | You keep a manifest of schema files | `files: [...]` in `cerial.config.ts` |

### The suffix

Name each file `<thing>.schema.ts` and keep them in a schema folder:

```
schemas/
  user.schema.ts
  post.schema.ts
```

```typescript
// schemas/user.schema.ts
import { model, f } from 'cerial/schema';

export const User = model('User', {
  id: f.record().id(),
  email: f.email().unique(),
  name: f.string(),
});
```

Every `*.schema.ts` under the schema folder is imported and its exported declarations are registered. Declaration files (`*.schema.d.ts`) and anything under `node_modules` are skipped. What a suffix file imports is not registered unless it carries the suffix itself.

### The entry module

Feature folders keep a model beside its controller and service, so no folder holds only schemas:

```
src/
  users/
    user.controller.ts
    user.service.ts
    user.schema.ts
  posts/
    post.controller.ts
    post.service.ts
    post.schema.ts
  schema.ts
```

```typescript
// src/schema.ts
import { defineSchema } from 'cerial/schema';
import { User } from './users/user.schema';
import { Post } from './posts/post.schema';

export default defineSchema({ models: [User, Post] });
```

```typescript
// cerial.config.ts
import { defineConfig } from 'cerial';

export default defineConfig({
  schemas: {
    app: { entry: './src/schema.ts', output: './src/db' },
  },
});
```

List models as exported bindings (`export const User = model(...)`). A `model()` call written inline in the `models` list is refused. Objects, tuples, enums and literals are not listed: they register by being imported. With no config at all, a `cerial.schema.ts` at the project root is the entry. The [entry module reference](/cli/configuration#entry-modules) has the full rules.

### Listed files

Name the files yourself when neither a folder nor an import graph describes your layout:

```typescript
// cerial.config.ts
import { defineConfig } from 'cerial';

export default defineConfig({
  schemas: {
    app: { files: ['./src/users/user.ts', './src/posts/post.ts'], output: './src/db' },
  },
});
```

A listed `.ts` file is imported whatever it is called. Paths are literal, with no globs. See [listed files](/cli/configuration#listed-files).

## How the modes combine

No mode switches another off. A schema entry can have a `path`, an `entry` and a `files` list at once, and Cerial generates the union of what they find.

- A declaration reached by more than one mode is generated once. A file found by its suffix, listed in `files` and imported by the entry is fine.
- Two different declarations with the same name are refused. The error names the file of each, and no client is written. Rename one.
- Everything an entry module imports counts as registered, with or without the suffix. A `*.schema.ts` file that is not an entry keeps its imports unregistered.

## Excluding a module

Exclusion lives in one place. The `ignore`, `exclude` and `include` fields and `.cerialignore` files apply the same way under all three modes, to suffix files, listed files, the entry and every module the entry imports. Patterns work as described in [Path Filtering](/cli/filtering).

Exclusion beats registration. If `defineSchema` lists a model whose module is excluded, the model is left out, and so is whatever only that module imports. The excluded module still runs when an entry imports it, because importing executes it. It just contributes nothing.

`cerial/handles.ts` is generated when a schema mixes `.cerial` files and TypeScript modules. Discovery never treats it as a schema under any mode, whether found by a path, listed in `files` or imported by an entry.

## What each command runs

Cerial runs project code to read a TypeScript schema, and `cerial.config.ts` is project code too. Here is what each command imports.

| Command | `cerial.config.ts` | Schema modules (`*.schema.ts`, entry, listed `files`) |
|---|---|---|
| `generate` | Runs | Imported |
| `migrate status`, `plan`, `apply`, `baseline` | Runs | Imported |
| `convert --to ts` and `--to cerial` | Runs | Imported |
| `format` | Runs | Not imported |
| `init` | Not run | Not imported |

`cerial.config.json` is data and never runs. A project of `.cerial` files alone has no schema modules to import, so only the config runs for it.

What gets imported:

- **Suffix files.** With no config, every `*.schema.ts` under the folder you run `cerial` from is a schema module and is imported, in whatever folder it sits. A `src/validation/user.schema.ts` written for another library is imported too. Dot folders, `node_modules` and `*.schema.d.ts` files are skipped. A `.cerial` marker file (`schema.cerial`, `main.cerial` or `index.cerial`) in the project root makes the whole project one schema root, so every `*.schema.ts` below it is imported as well. Name your own non-schema files something else, or put the schemas in a config and list them.
- **Entry modules.** The entry and every module it imports with a value import, at any depth and outside the project, packages included. `import type` and dynamic `import()` are not followed.
- **Listed `files`.** Imported wherever the path points, including a folder above the project.
- **Symlinks.** A linked schema module or folder is followed, and its target is imported.

:::warning
Running `generate`, `migrate` or `convert` in a checkout you have not read runs that checkout's TypeScript with your permissions. `format` runs its `cerial.config.ts`. Read a project before you run `cerial` in it, or run it in a container or a CI job with no secrets. `cerial init` is the one command that runs none of it.
:::

The note on [the config loader](/cli/configuration#config-file-formats) covers the config itself.
